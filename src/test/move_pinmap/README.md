# move_pinmap v2 — Move 板腳位自動對應測試

新洗/新焊的 Move 板腳位與舊板不同時，用這支獨立程式**在完全不需要 Hub、不需要打指令**
的情況下自動找出 PWM / DIR / 編碼器對應，並印出可直接貼回 `src/move/main.cpp` 的程式碼。

## 用法

```bash
pio run -e move_pinmap -t upload
pio device monitor -e move_pinmap        # 115200
```

上電後 **3 秒自動開始**（這 3 秒內按任意鍵可取消，改成手動模式），流程：

1. **腳位普查**：GP0~GP29 逐一以 pull-down / pull-up 讀值，印出「外部上拉 / 外部下拉 / 浮空」，
   用來對照實際接線（若結果異常，把這段貼回來即可診斷）。
2. **[1] 找 PWM + 編碼器**：先只掃 **GP2~GP13（馬達側）**，每腳「斜坡 18% → 45%」各 0.85 秒，
   同時統計所有其他腳的邊緣數：
   - 有輪子轉的那一腳 = **PWM**
   - 跳動最多的兩腳 = **該輪的編碼器 A/B**
   - 若兩腳邊緣數差距 >4 倍視為雜訊，忽略
3. **[1b] 找致能腳**（只找到 <2 輪時）：逐一候選腳拉 HIGH 再去試舊板的 4 個 PWM，
   哪一腳拉高馬達才會轉 → 就是 **EN/SLEEP/STBY**，之後全程保持拉高。
4. **[1c] 擴大掃描**：若仍不足 4 輪，才把範圍擴到 GP14 以上（此區多為編碼器輸入，
   ⚠ 可能推到編碼器輸出，2 秒內可按 Enter 跳過）。
5. **[2] 找 DIR**：對每個已找到的 PWM，先量 DIR=LOW 的有號正交計數當基準，
   再逐一候選腳拉 HIGH，**方向反轉**的那一腳就是 DIR（同時得到極性）。
6. **[3] 報表**：列出每輪 `PWM / DIR / ENC`、與舊板相同或已改變、DIR 正負計數，
   最後印出可直接貼回 `namespace Pin` 的區塊；若 A/B 與舊板相反或不相鄰也會提示
   （PIO `in pins,2` 只能讀相鄰腳，base 一律取較小腳）。

## 手動指令（自動跑完後或取消自動時可用）

| 指令 | 說明 |
|------|------|
| `run [duty%]` | 重跑全自動對應（預設 45%） |
| `dump` | 腳位原始電位普查 |
| `enc` | 每秒列出各腳跳變次數（手動轉輪確認編碼器） |
| `quad <a> <b>` | 即時有號正交計數（判斷方向 / A、B 是否成對） |
| `probe <pwm> <a> <b> [duty]` | 逐腳用 **50k 弱上/下拉**（不再 push-pull 硬推）印出轉向計數，找/確認 DIR |
| `roles <a> <b> <encA> <encB>` | **判斷兩隻腳誰是 PWM、誰是 DIR**：兩腳輪流當 PWM 跑 20%/60%，看轉速是否隨 duty 成正比、另一腳換電位是否讓方向反轉 |
| `verify` | 用目前量到的對應逐輪試轉，DIR 低/高各一次，印編碼器增減量 |
| `spin <pin> <duty>` | 單腳 PWM 輸出（Enter 停） |
| `dir <pin> <0\|1>` | 單腳固定輸出（測 DIR / EN） |
| `pwmoff` / `rel` | 停止所有 PWM / 全部釋放回「輸入 + pull-down」 |
| `pull <up\|down>` | 監看模式的內部上下拉 |
| `help` | 說明；**Enter** 可中止目前動作 |

## 為什麼 v1 會「沒動作」

- v1 用 25% 出力 → 常常推不動（新馬達/新輪子的靜摩擦）。
- v1 用「上下拉普查跳過被驅動腳」→ 驅動板輸入腳若有 10k 外部上下拉，會被誤判成
  「外部驅動」而整批跳過，於是什麼都找不到。
- v1 需要手動輸入 `scan` 才會開始 → 看起來像「不能用」。

v2 已移除上述三個問題：出力拉到 45%（含斜坡）、普查只印不跳過、開機自動執行。

## DIR 是怎麼找到的（原理）

DIR 本身沒有回授，只能「讓馬達轉 → 把某隻腳翻成相反電位 → 看編碼器轉向是否反過來」：

1. PWM 先跑到 45%（其他腳全 LOW，當基準），量 0.45 秒的有號正交計數（`+` = A 領先 B）。
2. 若基準幾乎 0，改成「其他腳全 HIGH」當基準再量一次（DIR 可能是低動作，或低電位時被煞住）。
3. 逐一候選腳翻成「與基準相反」的電位（非上拉，是硬推），再量一次；
   **同向 → 不是 DIR；反向 → 就是這輪的 DIR；同向但轉速大跳 → 角色互換（那隻才是 PWM）。**

> **已修正的兩個 bug（造成「DIR 全部找不到 / 量測瞬間 +0」）**
> 1. `dirBaseline()` 誤把 PWM 腳也改回輸入（`pinToInput(pwm)`）→ PWM 被關掉、馬達不轉。
> 2. 終端送 `\r\n` 時，命令後的 `\n` 被誤判成「按 Enter 中止」→ 量測一開始就 return 0。
>    現在 `\r` 之後緊接的 `\n` 會被吞掉。
> 另外本 core 的 `printf` 不支援 `%f`（會印成空），已全部改整數輸出。
>
> **3. 不再 push-pull 硬推候選腳**：實測發現硬推某些腳（很可能是 5V 編碼器輸出）
> 會把板子的 5V/邏輯拖歪，馬達直接停住 → 這就是「DIR 找不到」的假象。
> 現在 probe / roles 只用 50k 內部上/下拉；拉不動會標 `[拉不動/外部強驅動]`。

## 若還是沒找到

1. 確認馬達電源（VM）有電，驅動板 VCC / EN 是否要拉高（程式會自動嘗試找 EN）。
2. 把 `dump` 與 `[1/3]` 那段輸出貼回來，即可從腳位電位看出接線。
3. 可先 `dir <pin> 1` 手動逐一拉高猜致能腳，再 `run` 一次。
4. 候選腳位表在檔案上方 `kCandidates[]`，可自行增減（GP0/GP1 = UART0，不列入）。
