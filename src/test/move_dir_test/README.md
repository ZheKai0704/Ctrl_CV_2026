# move_dir_test — Move 新板「移動方向 / 極性」測試

新板腳位（實測）：

| 輪 | DIR | PWM | ENC (A/B) |
|----|-----|-----|-----------|
| FR | GP8 | GP9 | GP14 / GP15 |
| FL | GP6 | GP7 | GP16 / GP17 |
| BL | GP12 | GP13 | GP18 / GP19 |
| BR | GP11 | GP10 | GP20 / GP21 |

程式內部輪序一律 **[FL, FR, BL, BR]**（與 `src/move/main.cpp` 相同），
麥克納姆運動學、軸向極性、PIO 編碼器解碼全部沿用正式韌體，因此量到的極性可直接貼回 `main.cpp`。

## 建置 / 上傳

```bash
pio run -e move_dir_test -t upload
pio device monitor -e move_dir_test      # 115200
```

> `quad_phase.pio.h` 直接沿用 `src/move/`（此 env 已加 `-I src/move`），沒有複製一份。

## 建議流程

0. **先確認「腳位 → 角落」對應正確**（新板最容易錯的一步）
   ```
   w fl 20     # 轉的真的是左前輪嗎？fr/bl/br 也各試一次
   ```
   若指到的角落不對，`namespace Pin` 的輪別要對調，否則再怎麼調極性都會亂轉。

1. **驗證馬達方向**
   ```
   fwd 25
   ```
   四輪應該都往「車頭方向」轉。
   - 有哪一顆反了 → 最省事是 `wizard`（見下），或手動 `pol fr -1` 再 `cal` 重跑。
   - `back 25`、`left 25`、`right 25`、`cw 25`、`ccw 25` 逐一驗證。
     `left/right` 若與實際相反，交換兩者即可（車體座標定義問題，不是接線錯）。
2. **自動量測編碼器極性**
   ```
   cal
   ```
   每輪以「韌體 +25%」正轉 0.8 秒，量原始計數 → 決定 `kEncReadPolarity`。
   某輪 `raw=+0` 代表編碼器沒接好或 A/B 腳不對。
3. **驗證 DIR 腳歸屬（選用）**
   ```
   dirtest fl
   ```
   DIR=LOW / DIR=HIGH 各轉一次，計數應該反向；方向沒反代表這支腳不是該輪的 DIR。
4. **輸出設定**
   ```
   report
   ```
   印出可直接貼回 `src/move/main.cpp` 的 `namespace Pin` 與兩個極性陣列。

## 指令表

| 指令 | 說明 |
|------|------|
| `fwd` / `back` / `left` / `right` / `cw` / `ccw` `[duty%]` | 四輪同動（預設 25%，上限 55%） |
| `w <fl\|fr\|bl\|br> <duty%>` | 單輪，正 = 韌體正轉慣例，可負 |
| `stop` / 空行 Enter | 停止 |
| `cal` | 自動量測 `kEncReadPolarity` |
| `wizard` / `dirfix` | 逐輪問「往車頭 f / 車尾 r」，自動算 `kWheelPolarity` 並自動 `cal` |
| `same [duty]` | 四輪都直接 `DIR=L`（忽略 `motorPol`），看原始硬體方向 |
| `cycle [duty]` | 四輪 fwd on 2s / off 0.6s ×5（判別電源/驅動板保護） |
| `sweep [ms]` | 四輪 10→45% 每段 `ms`（預設 3500），找斷電門檻 |
| `dirtest <輪>` | DIR 低/高各轉一次，驗證 DIR 腳 |
| `pol <輪> <-1\|1>` | 改 `kWheelPolarity`（即時生效） |
| `encpol <輪> <-1\|1>` | 改 `kEncReadPolarity`（即時生效） |
| `enc` | 待機：手轉輪子，印原始計數 |
| `report` / `map` / `help` | 報表 / 腳位表 / 說明 |

## 輸出怎麼看

```
[fwd 25%]
  FL DIR=L (+25%)  d=  +412  rps=+82/100  ok
  FR DIR=L (+25%)  d=  -398  rps=-80/100  XX
```

- `DIR`：實際 DIR 電位（L = 正轉慣例）
- `(%)`：實際送到驅動板的等效輸出（已含 `motorPol`）
- `d`：該量測窗的編碼器原始增量
- `rps=/100`：套用 `encPol` 後的轉速（×100，整數輸出，此 core 的 `printf` 不支援 `%f`）
- `ok` / `XX`：輸出方向與回授方向是否一致。`XX` 表示該輪馬達極性或編碼器極性要翻。

## 安全

- 四輪 / 單輪出力上限 55%，長轉請架空車身。
- `cal`、`dirtest`、`cycle` 期間按任意鍵即中止；停止一律 PWM=0。
- 程式只驅動本表列出的 8 支馬達腳位（GP6~GP13），不動 GP0/GP1（UART0）。

## 出力中「突然全部不轉」（程式沒停：PWM/DIR 仍是 25%）

現象：狀態列印顯示 `DIR` 與 `(%)` 都還在，但 `d` 從正常值 → 下降 → 變 0，四輪同時發生。
這代表程式仍在輸出，是**外部**讓馬達（含編碼器）斷電，常見原因：

1. 電池 BMS / 保險絲 欠壓或過流保護（四輪同時起轉的衝擊最大）。
2. 驅動板過流 / 過溫保護，或驅動板的 VM、5V 掉。
3. 5V 邏輯/編碼器供電的降壓 IC 進入限流（馬達與編碼器會一起停）。
4. 底盤頂到牆 / 輪子卡住 → 堵轉保護。

判別方式：

- `cycle 25`：on 段若「又恢復轉」→ 保護型（電源/驅動板），斷電重置後才會完全復原。
- `w fl 25` 單輪、`fwd 10` 低出力：會不會也停？單輪不停 → 幾乎確定是供電不足。
- 量電池 VM 電壓與 5V 在 fwd 25 時的變化；摸驅動板與降壓 IC 溫度。
- 程式內建保護：出力但 1 秒無回授 → `[STALL]` 警告；3 秒 → 自動停，避免持續堵轉。

## 馬達極性怎麼來的（`wizard` 原理）

`fwd` 的韌體命令固定是 **FL=+ FR=− BL=− BR=+**（左右鏡像）。
設 `p[i]` = 「DIR=L 時該輪實際把車往車頭(+) 或車尾(−)推」，
則 `kWheelPolarity[i] = p[i] × fwdSign[i]`，`fwd` 時四輪就都會往車頭。
`wizard` 就是逐輪問你 `p[i]`，算完自動重跑 `cal`（馬達極性一改，編碼器極性必須重量）。

> 麥克納姆輪的**機械安裝**也要對：對角兩顆同向、左右兩顆互為鏡像。
> 四顆裝成一樣的話，極性怎麼調都會斜走／亂轉。

## `XX` 是什麼意思

`XX` 只代表「該輪**韌體命令**方向」與「該輪回授方向」不一致，**不代表馬達接反**。
比較基準是 `cmd`（firmware 命令），與 `cal` 定義 `encPol` 的方式一致；
不要跟 `DIR` 電位比（`motorPol=-1` 的輪子兩者符號本來就相反）。
跑一次 `cal` 後應該四輪都是 `ok`；也可手動 `encpol bl -1`。
馬達方向是否正確，要看車子實際往哪裡走（`fwd / back / left / right`）。
