# PCA9685 角度對應測試（0° ~ 180°）

驗證 RP2350 → PCA9685 → 伺服馬達的角度對應，並用來校正伺服實際行程。

## 1. 對應公式（每通道獨立）

每個通道有自己的 **0° 脈寬（zeroUs）**、**行程（spanUs = 180° - 0°）**、
**工作角度範圍（minDeg~maxDeg）** 與 **啟用開關**：

```
effDeg   = invert ? (180 - deg) : deg         (invert=1 → 0°/180° 對調)
pulseUs  = zeroUs + spanUs × effDeg / 180     (deg 會被夾在 minDeg~maxDeg)
offCount = round(pulseUs × 4096 / 20000)      # PCA9685 12-bit, 20ms 週期
```

所有設定存於 EEPROM，重開機保留；`l` 可列出目前設定。

出廠預設：`zeroUs = 600μs`、`spanUs = 1800μs`（180° = 2400μs）。

目前已套用的校正（0° 逐通道校正，**180° 統一維持 2400μs**）：

| 1 | 789 | 2400 | 1611 | **反向** | **10~180°** | 已校正 |

| 3 | 789 | 2400 | 1611 | **反向** | **10~180°** | 已校正 |
| 4 | 824 | 2400 | 1576 | 正向 | 0~180° | 已校正 |

> 反向通道：邏輯 0° 輸出原本 180° 的脈寬，邏輯 180° 輸出原本 0° 的脈寬。
>
> **工作角度是「實體」角度**（機械安全範圍），反向時邏輯範圍會鏡射：
> - CH1/3/5（實體 10~180°、反向）→ 邏輯可用 **0~170°**；
>   邏輯 180° 會被夾到實體 10°（`p` 讀回約 170°），避免走到會抖的實體 0°。
> - CH11/13/15（實體 0~180°、反向）→ 邏輯 0~180° 正常。

> 行程 = 180°脈寬 − 0°脈寬，每通道不同。要調整：
> `ma <ch> <0°us> <180°us>`（最直接）、`mz` 只改 0°、`ms` 只改行程。
> 停用通道在 `A`（全通道）與 `W`（輪流掃描）會被跳過，`a` 會拒絕。

> 12-bit 一個 tick = 20000/4096 ≈ 4.88 μs ≈ 0.44°，所以角度誤差 < 0.5°。

## 2. 接線

| RP2350 | PCA9685 |
|---|---|
| GP4 | SDA |
| GP5 | SCL |
| 3V3 | VCC（邏輯電源，勿接 5V） |
| GND | GND（與伺服電源共地） |
| — | V+ ← 伺服獨立 5~6V |
| — | OE 拉低 |

SDA/SCL 需 4.7kΩ 上拉（模組多已內建）。I2C 使用 **100kHz**（400kHz 在長線上不穩）。

## 3. 建置 / 燒錄

```bash
pio run -e pca9685_angle -t upload
pio device monitor -e pca9685_angle      # 115200
```

## 4. 序列命令

| 命令 | 說明 |
|---|---|
| `s` | 掃描 I2C（確認 0x40） |
| `i` | 初始化（50Hz、16 通道關閉） |
| `l` | 列出 16 通道端點 |
| `d [ch]` | 該通道 0~180°（每 15°）對應表 |
| `v [ch]` | 0~180° 每 15° 寫入→讀回驗證（預設 CH0） |
| `a <ch> <deg>` | 指定通道轉到角度（可小數） |
| `A <deg>` | 全部通道同角度 |
| `p <ch>` | 讀回該通道角度/脈寬 |
| `t <ch> <fromUs> <toUs> [stepUs] [holdMs]` | 微步走查脈寬（找抖動/異音的安全端點） |
| `w <ch> [step] [ms]` | 單通道 0↔180° 來回掃描 |
| `W [step] [ms]` | 全通道輪流掃描（找有接伺服的通道） |
| `q` | 停止掃描 |
| `c <ch> <us>` | 直接輸出脈寬（忽略限制，用來找安全極限） |
| `m <minUs> <maxUs>` | 設定全部通道 0°/180° 脈寬 |
| `ma <ch> <minUs> <maxUs>` | 設定單通道 0°/180° 脈寬（存 EEPROM） |
| `mz <ch> <zeroUs>` | 只改 0° 零點（維持行程） |
| `ms <ch> <spanUs>` | 只改行程（180° - 0°） |
| `md <ch> <minDeg> <maxDeg>` | 設定工作角度範圍（例：`md 1 10 180`） |
| `me <ch> <0\|1>` | 啟用 / 停用通道（停用後 `A`/`W` 跳過） |
| `mi <ch> <0\|1>` | 角度反向（1 = 0° 與 180° 對調；工作角度以實體角度為準） |
| `mr <ch>` / `mR` | 回復預設端點（單通道 / 全部） |
| `r` | 重新開機（驗證端點是否保留） |
| `o <ch>` / `x` | 關閉單通道 / 全部關閉 |
| `n <addr>` | 變更 PCA9685 位址 |

## 5. 自動化測試

```bash
# 完整自動測試（對應表 + 3 次寫入讀回）
~/.platformio/penv/bin/python tools/pca9685_angle_test.py

# 先燒錄再測
~/.platformio/penv/bin/python tools/pca9685_angle_test.py --upload

# 逐點定位（每 15° 停 1 秒，肉眼看伺服）
~/.platformio/penv/bin/python tools/pca9685_angle_test.py --visual 0

# 連續掃描 8 秒
~/.platformio/penv/bin/python tools/pca9685_angle_test.py --sweep 0 --seconds 8

# 端點校正（輸入安全脈寬）
~/.platformio/penv/bin/python tools/pca9685_angle_test.py --calibrate 0

# 指定端點（需與固件 ma 一致）
~/.platformio/penv/bin/python tools/pca9685_angle_test.py --min 600 --max 2400
```

離開碼：`0` 全 PASS、`1` 有 FAIL、`2` 連線/裝置問題。

## 6. 端點抖動 / 嗡嗡叫處理

伺服在 0° 或 180° 持續抖動（hunting）＝脈寬落在它內部電位器的死點或機械阻擋區，
伺服一直「想再過去一點」，會持續吃電流並發熱。

處理順序：

1. **先關閉**：`x`
2. **微步找安全值**（一次只動一點，邊聽邊看）：
   ```
   t 3 650 850 10 800      # 從 650μs 往上，每 10μs 停 0.8 秒
   t 3 2350 2150 10 800    # 從 2350μs 往下
   q                       # 中途停止
   ```
   記下「開始不再抖動」的脈寬。
3. **寫入該通道端點**（自動存 EEPROM）：
   ```
   ma 3 700 2300
   a 3 0 ; a 3 180          # 再確認兩端都不抖
   ```
4. 全部通道都偏小的話，可一次設定：`m 700 2300`

硬體面向（抖動常見真正原因）：

- 伺服電源要**獨立 5~6V BEC**，不要吃 Pico 的 5V/3V3
- V+ / GND 併一顆 **470~1000μF 電解電容**（靠近 PCA9685）
- 全部 GND 共地，線材不要太細太長
- 多顆伺服同時到極限時電流最大，容易整組抖動 → 先只接一顆測試
- 數位伺服在極限附近本來就比較容易微抖，把範圍再縮 20~50μs 通常就好

> PCA9685 一個 tick = 4.88μs ≈ 0.44°，量化誤差不會造成肉眼可見的抖動。

## 7. 判讀

- `[VERIFY] RESULT PASS 13/13, 單調遞增=YES, I2C 錯誤 +0`
  → 角度→暫存器→讀回完全正確，且 offCount 隨角度單調遞增。
- 表中有 `FAIL` → 該角度寫入/讀回不一致（先看 I2C 錯誤數，多半是線材/上拉）。
- 伺服在某角度**持續嗡嗡叫/發熱** → 已到機械極限：
  1. 立刻 `x` 全部關閉
  2. 用 `c <ch> <us>` 慢慢逼近（例：`c 3 650`、`c 3 600`…）找出不會叫的最小值
  3. `ma <ch> <minUs> <maxUs>` 寫入該通道安全範圍（自動存檔）
- 伺服實際角度與命令不符 → 同樣用 `ma` 校正該通道端點。

⚠️ 伺服馬達無法被偵測。`v` 只驗證「暫存器內容正確」，實際有沒有動、
方向對不對仍要靠 `--visual` / `--sweep` 肉眼確認。首次測試請空載、小角度。
